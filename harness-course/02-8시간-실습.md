## 블록 3. 기획 — AI가 나를 인터뷰 (60분)

### 목표
"태그 기능"을 **확정 주문서 → 설계도 → 이슈 2개**로 만들기

### 3-1. 처음 주문서 (5분)
`docs/features/tag/spec-original.md` 를 **학생이 직접** 3줄로 씀:
```markdown
# 태그 기능
메모에 태그를 달 수 있다.
태그로 메모를 걸러 볼 수 있다.
```

### 3-2. 🎤 AI 인터뷰 (20분)
```
docs/features/tag/spec-original.md 를 읽고, 코드베이스를 먼저 살펴본 다음
구현 전에 확인해야 할 것들을 나한테 질문해줘.
- 반드시 한 번에 하나씩만 질문해
- 각 질문마다 너의 추천 답과 이유를 같이 말해줘
- 10개 이내로 끝내줘
```
→ 학생이 하나씩 답함. (최대 개수, 길이, 대소문자, 중복, 공백, 빈 값 등)
인터뷰 끝나면:
```
인터뷰에서 결정한 내용을 docs/features/tag/spec-fixed.md 로 정리해줘.
- 각 결정마다 "왜" 그렇게 정했는지 한 줄씩
- 맨 아래 "용어 정의" 섹션 (태그, 태그 칩, 필터 등)
```

💬 **질문 던지기**: "인터뷰 전 3줄 vs 후 spec-fixed — 몇 가지가 새로 정해졌나요?"

### 3-3. 설계도 + 기술 결정 (20분)
```
spec-fixed.md 를 바탕으로 docs/features/tag/prd.md 를 만들어줘.
섹션: 개요 / 사용자 이야기 / 기술 결정 / 이번에 안 만들 것 / 용어 정의
"기술 결정"은 아직 TODO 로 두고,
태그를 저장하는 방법 3가지 안을 아래 기준으로 표 비교해줘:
데이터 구조 / 고쳐야 할 곳 / 기존 코드와 비슷한 정도 / 테스트 쉬움 / 복잡도
```
→ **학생이 직접 고른다** (예: "메모 객체 안에 tags 배열")
```
A안으로 결정했어. 기술 결정 섹션을
상황 / 다른 후보 / 결정 / 결과(장점과 단점 모두) 4가지로 써줘.
"이번에 안 만들 것"에는: 태그 색상, 태그 이름 수정, 자동완성, 태그 여러 개 동시 필터.
```

### 3-4. 케이크 세로로 자르기 (15분)

```
1. 메모에 태그 추가/삭제
2. 태그 클릭으로 메모 필터
- 각 이슈는 그것만 끝내도 사용자가 화면에서 확인할 수 있어야 해
- 각 이슈에 "~일 때 / ~하면 / ~된다" 형식 완료 체크리스트 3~5개
```
```

```


### ✅ 체크포인트
- [ ] spec-fixed.md 에 "왜"가 적혀 있다

## 블록 5. TDD — 이슈 #1 (80분)

### 목표
**시험 문제 먼저 → 통과 → 정리** 한 바퀴를 손으로 돌리고, 각 단계를 스킬로 만들기

> 📌 진행 방식: 각 단계에서 **① 먼저 스킬을 만들고 ② 바로 실행**합니다. 다음 블록에서 재사용하기 위해서예요.

```bash
git checkout -b feat/tag-1
```

### 5-1. 시험 범위 정하기: /test-scenarios (15분)
```
.claude/skills/test-scenarios/SKILL.md 스킬을 만들어줘. 이슈 번호를 인자로 받는다.
절차:
1. gh issue view <번호> 로 이슈와 완료 체크리스트 읽기
2. 함수 시그니처(입력/출력/에러 메시지)를 제안 → 사용자 승인 받기. 구현 금지
3. 테스트 시나리오를 [정상] [경계] [예외] 로 분류해서 제안
   형식: "함수명 should ... when ..."
   경계값은 최대-1, 최대, 최대+1 을 꼭 포함
4. 완료 체크리스트 항목이 전부 시나리오에 들어갔는지 대조표 → 사용자 승인
5. 결과를 docs/features/tag/scenarios-<번호>.md 에 저장
```
```
/test-scenarios 1
```
💬 **질문 던지기**: "태그 최대 5개면 경계 시나리오는 몇 개, 어떤 숫자로?"

### 5-2. 🔴 Red: /tdd-red (15분)
```
.claude/skills/tdd-red/SKILL.md 스킬을 만들어줘.
절차:
1. scenarios-<번호>.md 의 시나리오를 Vitest 테스트로 변환 (it 설명 = 시나리오 문장)
2. 구현 파일은 함수 모양만 만들고 본문은 throw new Error('not implemented')
3. 구현 코드 작성 절대 금지
4. npm test 실행 → 모든 테스트가 "not implemented" 때문에 실패하는지 확인
   "Cannot find module" 같은 에러면 실패가 아니라 고장(Broken)이니 고친다
5. React 컴포넌트 테스트는 getByRole > getByText 우선, 내부 state 검사 금지
```
```
/tdd-red 1
```
→ 화면에 **"N failed, 0 passed"** 🔴 → 다 같이 확인

### 5-3. 🟢 Green: /tdd-green (20분)
```
.claude/skills/tdd-green/SKILL.md 스킬을 만들어줘.
절차:
1. 실패한 테스트를 하나만 골라 그것만 통과하는 최소 구현
2. 테스트에 없는 기능 추가 금지 (YAGNI). 테스트 파일 수정 금지
3. 매번 npm test 전체 실행 → 다른 테스트가 깨지면 방금 변경 되돌리기
4. 같은 테스트 5번 실패하면 멈추고 보고
5. UI 를 만들 때는 docs/design/*.md 를 참고
6. 실패 카운트가 0 이 될 때까지 반복, 진행 상황을 "남은 실패: N" 으로 보고
```
```
/tdd-green 1
```
🎮 **실시간 중계**: 실패 개수가 12 → 11 → 10 … 줄어드는 걸 같이 보기

### 5-4. 🔍 검사관: @ac-verifier (10분)
```

실제로 그걸 만족하는지 독립적으로 판단한다. 코드는 수정하지 않는다.
```
